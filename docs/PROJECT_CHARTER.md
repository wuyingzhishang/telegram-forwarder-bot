# 项目立项与当前范围

- 项目：Telegram 消息提取与转发机器人
- 立项日期：2026-10-19
- 项目属性：个人自托管项目
- 当前状态：Docker Compose 部署版，持续迭代

## 目标

让管理员用 Telegram 菜单或仪表盘维护来源、目标和转发规则；让有权限的用户提交可转发消息，或由已授权的 Telegram 用户会话读取来源，再由 Bot 发布到已配置目标。目标频道和群组由数据库管理，不写死在代码中。

## 当前方案

用户手动转发消息 → Bot 私聊 → 用户选择目标 → Bot API 复制。

消息链接、用户账号实时规则和历史克隆 → Telethon 用户会话读取已授权来源 → Bot API 上传或发布 → 已配置目标。

一个 Bot 负责管理菜单和目标发布。Bot API 私聊提交不需要来源频道管理员权限，但消息必须允许转发。链接提取、用户账号来源规则和历史克隆需要单独启用 Telethon 用户会话；它不能读取该登录账号无权访问的私密聊天。

## 已交付范围

- Telegram 原生命令菜单提供 `/start`、`/rules`、`/newrule`、`/history`、`/targets`、`/addtarget` 和 `/cancel`。
- `/start` 为管理员显示管理入口，为普通用户显示提交说明和帮助入口；按钮操作会在后端再次校验权限。
- 规则可在 Bot 菜单和仪表盘创建、编辑、启停、删除；来源和目标均为可配置值。
- 规则支持来源读取模式、消息类型、包含/排除词、逐条或按相册筛选、复制/转发来源展示、媒体说明文字处理、删除/替换词、前后缀、移除链接、URL 按钮、相册发送模式和规则名称。
- 用户可把可转发消息私聊发送给 Bot，并选择一个或多个已配置目标。Bot API 复制不会附带原消息来源链接。
- 用户可在 `/start` 设置自己的默认转发对象；之后本人提交消息并选择发布账号后会自动发送到默认目标，其他用户的偏好不受影响。
- 可选用户会话支持链接提取、用户账号实时规则和最多最近 5000 条消息的历史克隆。任务记录支持暂停、继续和取消。
- 仪表盘提供规则、目标、活动记录和 Bot 心跳等管理视图；Docker Compose 也提供可选 Cloudflare Tunnel profile。

## 运行前提

- Bot API 来源模式只能处理 Bot 实际能收到的新消息。Telegram 频道通常要求 Bot 具备管理员身份才能收到频道更新。
- 用户账号来源模式、消息链接提取和历史克隆要求配置 Telegram API ID/API Hash，完成一次本地交互登录，并启用 `user-session` profile。
- 用户账号必须已经加入或获准访问私密来源。私密链接本身不授予访问权。
- 目标频道需要 Bot 有发布权限，目标群组需要 Bot 有发送权限。

## 当前限制

- 历史克隆按最近消息数量选择，范围为 1–5000 条；当前没有日期区间、媒体类型筛选或失败项单独重试。
- 用户会话需要下载媒体再经 Bot API 上传；速度、单文件限制、网络和 Telegram 限流都会影响处理。
- 受保护/禁止转发的聊天或消息不处理，不尝试绕过 Telegram 内容保护。
- 规则的正文改写和媒体说明处理适用于复制模式；保留原转发来源时不执行这些改写。
- 去除来源标记不等于获得内容再发布授权。提交者和运营者需要确保拥有相应权利。

## 部署与隐私

Docker Compose 是主要部署方式。仪表盘默认只绑定本机回环地址；远程访问可通过 HTTPS 和 Cloudflare Tunnel。Cloudflare Workers 不承担持续运行的 Bot polling、MTProto 会话和 SQLite 任务队列。

Bot Token、Telegram 用户会话和仪表盘密码均为凭据。不要提交 `.env`、SQLite 数据库或 `.session` 文件。用户会话保存在单独的持久化卷中，只有管理员负责登录和维护。
